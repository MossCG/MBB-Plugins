# AI 主持只做只读的回合叙述员，默认关闭、失败即降级模板，关闭时与纯工具模式完全一致

状态：accepted（2026-10-22）

第一版把 AI 主持定位成「回合叙述员」而不是代理 KP：只读局面，只产纯文本叙述与可选建议动作，零状态变更；数值、判定与状态迁移仍由 规则引擎 / 局面状态机 / 数据模型 的既有路径算出，人类 KP 是唯一权威，随时可用自己的叙述覆盖 AI 输出。边界靠一张副作用清单兜住：AI 的可见副作用只有群消息与审计行，AI 子状态（aiEnabled / aiSuspendedUntil / aiFailStreak）的写入一律经 SessionService 的群锁 + 单语句 CAS 提交，TrpgAiHostService 只发写请求、不直接写库；AI 也不得绕过 指令集 的判定顺序、权限矩阵与单语句 CAS，调用发生在群锁之外、不参与 CAS，因此超时不会卡住指令。之所以收紧到「只读 + 单一入口」，是因为 AI 的输入是模型输出而不是系统事实：一旦允许它写状态，系统结果与模型断言就无法区分，事后只能靠日志考古；收在一个协调服务后面，也让将来换实现不牵动状态机。

开关分三层且默认全关。最外层 aiHost.enabled 默认 false，由 BOT_ADMIN（含 OWNER）在插件配置里打开，只在插件加载时读取一次——改动它必须重启或重载插件，`/reload` 不重载插件配置；全局关时任何群都不可开。第二层是按局授权：T1 建局固定 ai_enabled=false，KP 在招募期用 `/trpg ai on` 开启，不新增 start 参数（插件先例调研 已否掉 Poll 多步询问的内存 Map）。第三层是局内 `/trpg ai on|off`：开是 KP 或 BOT_ADMIN，关是 KP / GROUP_ADMIN / BOT_ADMIN，只允许在招募与进行中，私聊拒绝、冷却 1 秒；判定顺序沿用 指令集（黑名单 → 群内 → 权限 → 状态 → 参数 → 冷却 → 执行），全局未启用时 ai on 按既有的「当前状态不可用」拒绝，不新增拒绝类别。挂起是独立的 AI 子状态，不改变授权，也不新增局状态，四态模型不变。v1 只交付这一层的壳：配置项、开关读取、`/trpg ai` 参数解析与全局关拒绝、空实现，零 AI 调用、零审计写入，ai_enabled 也不落库（授权持久化随 数据模型 在 v1.1 落地）。

触发按「关键节点立即」与「自由行动合并」二分：`/trpg scene` 推进、KP 或 BOT_ADMIN 代掷的 check / opposed / san 结算、`/trpg begin` 完成后的开场叙述立即触发一次，不进合并窗口；局内成员的自由文本行动与玩家本人发起的自助 check 进同群合并窗口，20 秒或 5 条先到先触发，5 条先到时立即结算并取消定时器，窗口内事件按事件序号拼成一次调用，窗口定时器走 Scheduler 端口且不持久化（重启丢窗、不补发）。只有「进行中」才调用，无局 / 招募 / 已结束一律走模板，而招募与结束公告本来就由 呈现规范 模板负责。排队与并发是硬上限而不是软限流：每群一条串行队列、待发上限 3，插件全局并发 2（启动时再与 MBB-AI `status()` 的 maxConcurrent 取 min），全局等待上限 4，超限不排队、直接按 queue_full 降级；队列项记入队时间，等待超过 65 秒（20 秒窗口 + 45 秒墙钟）即移出并按 queue_full（reason=queue_age）降级，避免第 2、3 条各等满 45 秒。超时做两层：插件侧墙钟 45 秒到点即放弃等待、立即释放插件槽位并记 timeout，传给 MBB-AI 的 timeoutSeconds 只有 10 秒，因为 MBB-AI 内部最坏约 30 秒（等许可 10 + connect 10 + read 10），单传 45 秒根本约束不到等待许可那一段。retryCount=0；去重键是「局号 | 场景版本 | 窗口首序号 | 窗口末序号」，同键只调用一次、结果缓存 60 秒。代价与理由是同一个：MBB-AI 的调用同步阻塞、被放弃的调用无法取消，只能用「不重试 + 并发自限 + 队列超龄」把最坏影响压在单次请求上。

降级表逐行对应一种可观察结果，出口只有「模板叙述 + AI 暂不可用提示」与「明确静默」两种，不允许失败后群聊长时间无响应：

| 情形 | 动作 | 计入失败 |
| --- | --- | --- |
| 全局关 / 本局未授权 | 纯工具模式，不调用、不发提示、不写审计 | 否 |
| MBB-AI 未安装（服务为 null）/ disabled / interrupted / 未列出的 errorType | 模板 + 提示 | 否 |
| 队列已满（每群 3 / 全局 4）或队列项等待超过 65 秒 | 模板 + 提示 | 否 |
| busy / 墙钟 45 秒到点 / network / http_4xx / http_5xx | 模板 + 提示 | 是 |
| 验证拒绝且重试一次后仍失败 | 模板（整条替换） | 是 |
| 同局连续 3 次失败（成功清零） | 挂起 10 分钟、提示一次、清空本群待发队列 | — |
| finishReason=length | 截断到 300 字按成功处理 | 否 |
| 结果返回时场景版本已变 | 丢弃不发（stale） | 否 |

计数口径决定挂起：只有真实调用失败（busy、墙钟 timeout、network、http、验证失败）计入连续失败，成功一次清零，queue_full、未授权、unavailable 不计。连续 3 次失败把 aiSuspendedUntil 写成当前时间 + 10 分钟并把 aiFailStreak 清零（0 哨兵，不落 NULL），同时清空本群待发队列、在途请求按 skipped 丢弃。挂起判定是惰性的：每次请求前比较注入的 Clock 与落库时间戳，重启后按列里的时间继续生效，不需要内存定时器；也不自动恢复，恢复只能由 KP 显式 `/trpg ai on`（清挂起、清计数、清本局去重缓存），`/trpg ai off` 使挂起自然失效。模板来源是剧本可配的场景级 fallback 叙述，缺省回退内置通用模板（客观事实播报 + 提示）。

输出契约按「清洗后的纯文本」兑现：不用 JSON 包裹、不用代码块、不用 Markdown 列表语法，因为 MBB-AI 对所有 content 无条件 toPlainText，任何包裹语法都会被剥掉。叙述正文不超过 300 字（按清洗后字符计，不含落款与提示），超出截断并记 truncated；可选建议动作单独一行、前缀「建议：」、最多 3 条，白名单只有调查/观察、交谈/询问、移动/前往、等待/休息、使用/查看物品、尝试技能六个大类且不含数值，非白名单整行丢弃，解析前先剥掉行首的「- 」「* 」「+ 」（MarkdownUtil 会把 `*` 与 `+` 归一成「- 」）。断言语义扫描命中 HP、生命值、SAN、理智、属性或技能加减数值、检定成败结论、替 KP 宣布推进，即视为越权：丢弃该段并重试一次，仍失败则整条走模板。审计表 plugin_mbb_trpg_ai_trace 只存元数据（局号、群号、事件序号、触发类型、结果状态、降级原因、errorType、attempts、耗时毫秒、finishReason、usage、cached）与输出前 240 字预览，不存完整提示词与完整输出，受 aiHost.traceEnabled 控制、按 168 小时与 5000 行双重封顶，写入尽力而为——失败只记插件日志，不阻断叙述、不计入失败。提示词分稳定前缀 / 可缓存中段 / 动态区三段，总预算 6000 字、动态区至少保留 1500 字；在场角色只给名字与公开状态标签、不给具体数值，未解锁线索只给后果摘要——这是防越权的第二道闸，直接降低模型断言数值的诱因。

## 考虑过的选项

- **让 AI 代 KP 推进回合或直接改状态**：能力上限最高，但人类 KP 的权威无从落地，AI 写入会绕过 指令集 的判定顺序与单语句 CAS，系统结果与模型断言再无法区分，事故只能靠日志考古；因此改为只读 + 建议动作白名单。
- **只设一层超时（给 MBB-AI 传 45 秒，或只设插件墙钟）**：前者约束不到 MBB-AI 等待许可的 10 秒，实际最坏超过 45 秒；后者放弃的线程仍继续占用 MBB-AI 许可。两层分别管「群聊不卡」与「槽位不长占」。
- **失败重试（retryCount≥1 或退避重试）**：busy 本来就是许可等待超时的产物，重试只会与其他插件争抢同一批许可，把单局失败放大成全局拥塞；重试只保留给输出验证失败，且同一次入队最多 2 次调用、共享同一插件槽位与同一 45 秒墙钟，第 1 次验证拒绝只记 attempts=1、不计失败。
- **用内存定时器在 10 分钟后自动恢复挂起**：重启即失效，且自动恢复会让坏 provider 在无人知情下继续被打；改为惰性判定 + 落库时间戳，恢复必须由 KP 显式 `/trpg ai on`。
- **用 JSON 契约约束输出并做剧透过滤**：清洗层对所有 content 无条件 toPlainText，JSON 与 Markdown 包裹都不可兑现；剧透过滤成本高、误杀多，改为分层素材（未解锁线索只给后果摘要）+ 审计抽查兜底。
- **审计存完整提示词与完整输出**：等于把群聊内容与剧本正文长期囤在库里，违反最小化，写入体积也会顶掉保留期；只存元数据与 240 字预览，表名与字段以 数据模型 / 数据模型与存档 定稿为准。

## 后果

- 下游全部落到兄弟规格的登记项上：指令集 只登记 `/trpg ai` 子命令与权限行、status 的 AI 行、begin 的开场叙述触发点、SessionService 的 readSnapshot 与 ai 子状态写方法，不改状态机与判定顺序；数据模型与存档 只保证 ai 三列（aiSuspendedUntil / aiFailStreak 用 0 哨兵）与 ai_trace 表就位、v1 建表不写行；呈现规范 提供可区分落款（「（AI 叙述）」与「（AI 暂不可用，本条为剧本原文）」）、300 字预算与「合并窗口只发一条」的版式；剧本格式 增场景 fallback 叙述与线索的「未解锁后果摘要 / 解锁后原文」两段文本；规格装配 把本契约装配成总文档一节并登记 AI 主持、回合叙述员、降级模板、AI 挂起四个术语。v1.1 开工前 数据模型 与 剧本格式 必须先关闭。
- 实现拆成 TrpgAiHostService（唯一入口与协调器）+ TrpgAiQueue / TrpgAiSuspendPolicy / TrpgAiAuthorization / TrpgAiPromptAssembler / TrpgAiOutputGuard / TrpgAiDegrader 六个协作类，端口 AiClient / Messaging / Clock / Scheduler / SessionView / TraceStore 全部构造注入；测试用假实现覆盖降级表每一行，不依赖真实网络与真实数据库，主测试缝是 TrpgAiHostService，次测试缝是 TrpgCommand 的 `/trpg ai` 分支且不重复服务语义。
- 完成判据可数而不是可感：关闭 AI 时 AiClient 调用数 = 0、AI 提示发送数 = 0、TraceStore 行数 = 0、不注册 AI 定时器，且局指令行为与纯工具模式完全一致；打开 AI 时降级表每一行都有可观察的模板叙述或明确静默，45 秒墙钟与全局并发 2 保证不长期占满 MBB-AI 槽位。
- 已知限制：被放弃的调用线程无法取消，最坏由 provider 的 10 秒 connect/read 收尾并继续占 MBB-AI 许可；全局并发 2 只是本插件自限，不声称与 MBB-AI 对齐（启动时取 min）；合并窗口定时器不持久化，重启丢窗不补发；stale 只靠 sceneVersion 单调递增识别，KP 的自由文本叙述不被识别，v1.1 不为此新增指令；挂起提示每个挂起周期只发一次、重启不补发；合并窗口是「丢窗」而不是「延迟补发」，重启后的第一条叙述只反映重启后的事件。
- 所有阈值都落在 `aiHost.*` 配置位而不是散在代码里，默认值随 v1 契约桩一起落地并冻结为：enabled=false、deadlineSeconds=45、providerTimeoutSeconds=10、retryCount=0、maxConcurrent=2、perGroupQueue=3、globalQueue=4、queueMaxAgeSeconds=65、mergeWindowSeconds=20、mergeWindowEvents=5、suspendFailStreak=3、suspendMinutes=10、dedupeCacheSeconds=60、promptBudgetChars=6000、dynamicMinChars=1500、narrationMaxChars=300、traceEnabled=true、traceKeepHours=168、traceMaxRows=5000；改动它们等于改契约，须同步 AI 主持 与本 ADR。
