# 规则引擎采用编译期 SPI，内置 d100 作为默认实现

状态：accepted（2026-10-21）

第一版需要「可插拔规则接口 + 内置 d100」（产品决策 D6），但主程序 apiVersion 0.3 冻结了插件 API 面，没有插件间依赖或类加载契约。规则集以编译期 SPI 接入：插件内定义 `RuleSet` 接口与 `RuleRegistry`，`onEnable` 时显式注册内置 `D100RuleSet`，配置只保存规则集 id（`ruleset: d100`）。第三方规则集等于在本插件内新增实现类并发版，不做跨 JAR 的 ServiceLoader 发现；成功等级阈值、奖惩骰上限、大失败口径等数值不暴露到配置。

## 考虑过的选项

- **配置驱动 JSON 规则**：可以改阈值不改代码，但等于自造一套规则 DSL，校验、文档与排错成本高，而剧本作者会把它当成扩展点。
- **跨插件 ServiceLoader**：最开放，但 0.3 没有插件依赖与类加载契约，主程序也未提供，当前无法落地。

## 后果

- 更换规则集需要改代码并发布新版本；v1 只有 d100，可接受。
- 状态机、存档与剧本只依赖 `ruleSetId`、`CheckRequest` 与 `CheckResult`，d100 的数值口径被挡在引擎边界内。
- 若将来主程序提供插件依赖机制，再评估服务发现，不需要改动现有检定契约。
