# MBB-Trpg 呈现规范（呈现规范）

状态：draft（2026-10-22）｜归属：设计规格「MBB-Trpg 跑团插件 · 第一版设计规格」分册｜下游：规格装配 装配进 `docs/MBB-Trpg.md`

本文件是全插件唯一的消息文案、字数上限、图片版式与渲染降级来源。指令集规格 把「文案归 呈现规范」的 8 处、AI 主持 的 5 条接口级要求、数据模型与存档 的排版归属，全部在这里收口。实现入口类名与配置键见 §8。

## 1. 结论摘要

- **群内只用 A 播报风**（`【标题】`），B 沉浸风与 C 极简风不采用，理由见 §2.2 与 ADR 0004。
- **一个事件一条消息，一条消息只用一个标题**。原型里「公告 / 场景 / 线索」拆三条的结论保留，但拆分理由从「太长」改成「三件不同的事」——每条消息脱离上下文也能读懂。
- **群内单条 ≤ 500 字**，超长按 §6 拆分，最多 3 条，剩下的折叠成一行提示；私聊不拆，超长折叠。
- **图片只有三种：情景卡、战报、脚本打印页**。角色卡与检定结果不发图（与原型 D3、现有小样一致）。图片一律 `ImageUtil.renderText` 760px 版式，主程序没有的自绘能力不引入。
- **图片失败一律回退纯文本**，回退文本冻结在 §7.4，游戏流程不因渲染失败中断。
- **AI 叙述正文 ≤300 字**，落款用括号区分「（AI 叙述）」与「（AI 暂不可用，本条为剧本原文）」，见 §4.3 与 §7.3。

## 2. 版式总则

### 2.1 单条消息结构

每一条 bot 发出的消息都长这样：

```text
【标题 · 子标题】
正文行（可多行）
空行
折叠行（可选，每类消息最多一行）
```

- **标题**：全角方括号 `【】` + 中文名；层级用半角空格 + 中点 ` · ` 分隔，最多两级（`【检定 · 聆听】`）。
- **正文**：一行一件事，每行尽量 ≤ 40 字；行间不加序号符号，不用 Markdown（QQ 不渲染 `**`、`#`、`| `）。
- **折叠行**：提示去哪里看全文（`…已私聊你全文。`），没有就不写。
- 不用 emoji、不用颜文字、不用连续装饰线（`────` 属于 B 沉浸风，不采用）。
- 冒号用全角 `：`，数值与单人信息用四角空格 `　` 对齐（沿用原型小样），多人并列用顿号 `、`。

### 2.2 为什么群内固定一种版式

跑团消息是**可复制的口述材料**：KP 会把 bot 发的场景叙述念出来，玩家会截图或转发。三种版式并存会让同一信息在不同群里长得不一样，也让「新手第一次进群能看懂每条消息」这条判据依赖运气。真机看下来，播报风在 QQ 的窄消息体里最省空间、标题最好扫，B 的装饰线在手机上会折行断成两截，C 的方括号和 `【】` 混排读起来像日志。因此 v1 固定 A，留 `presentation.style` 配置位但不提供 B/C 实现（配置值非 `broadcast` 时按 `broadcast` 处理并记一条 WARN 日志）。

### 2.3 标题词表（冻结）

标题只用下表里的词，新增词要先改本表再改代码。

| 分区 | 标题 | 用途 |
|---|---|---|
| 招募 | 【开团】【加入】【离开】【邀请】【接管】 | 局面变化 |
| 开局 | 【开局】【场景】【剧本】 | 进入内容 |
| 玩法 | 【检定】【对抗】【理智】【成长】【调整】 | 数值与判定 |
| 剧情 | 【线索】【触发】【AI 叙述】 | 信息与叙述 |
| 收尾 | 【结束】【结束确认】【战报】 | 收口 |
| 系统 | 【提示】【错误】【角色卡】【KP 提示】【剧本库】【恢复】【主持】 | 非剧情消息 |
| 查询 | 【局面】【帮助】【日志】 | 只读回执（`status` / `help` / `log`） |

标题后面可以带一个「 · 子标题」，子标题取角色名、技能名、场景标题、剧本名之一，不叠加。

### 3.4 /r 与 /roll

骰点指令的回复**不套标题**，直接用玩家输入的形态回话，一行内说完：

```text
/r 3d6+2 = 14
[r] 3d6+2 = 14
/r 1d100 = 34
```

- 单段省略 `[r]` 头；多段每段一行，末行是合计。
- 解析失败只回一行：`表达式不支持：3d6*2（只支持 NdM 与加法，最多 3 段）`，不套标题、不解释第二遍；同类错误 10 秒内不重复（沿用 指令集 的去重口径，由 指令集 的冷却逻辑实现，本文只负责文案）。

### 3.5 剧本库管理（S10）

全部标题沿用 §2.3 词表：列表用【剧本库】、详情/导入/删除/生成结果用【剧本】加子标题，受理与普通提醒用【提示】，失败用【错误】；不新增标题词。

| 标题 | 内容 | 上限 |
|---|---|---|
| 【剧本库】 | 每页 10 条的剧本摘要；有被跳过文件时附一行失败数 | 500 字 |
| 【剧本 · 剧本名】 | id、作者、人数/时长/规则集、场景/线索/结局计数、描述 | 500 字 |
| 【剧本 · 导入】 | 分段导入指引：模式、总量上限、空闲/绝对超时、end/cancel 控制字 | 600 字 |
| 【剧本 · 导入】 | 解析未完成：已收字节数/上限 + 第一条错误 + 继续或取消的指引 | 260 字 |
| 【剧本 · 导入】 | 校验未通过：本次已结束，前 5 条错误 + 原文存档位置 | 500 字 |
| 【剧本 · 剧本名】 | 导入成功：id、场景/线索/结局计数、是否替换、告警数、开团指引 | 500 字 |
| 【剧本 · 导入】 | 已取消，未写入剧本库 | 120 字 |
| 【提示】 | 生成已受理：题材、人数、时长、完成后 @ 发起人 | 120 字 |
| 【剧本 · 剧本名】 | 生成成功：同导入成功格式 | 600 字 |
| 【错误】 | 生成失败：`E_AI_*` 错误码 + 中文原因 + 前 5 条校验错误 + 原文存档位置 + 手动退路 | 600 字 |
| 【剧本 · 删除】 | 已删除的剧本名与 id | 120 字 |

导入/生成失败的错误行按 §2.1「行间不加序号符号」逐行平铺，不写 `- ` 前缀。

### 3.6 AI 主持（v1.1）

标题沿用词表，只用一级【AI 叙述】；§2.3 的冻结标题表只放角色名/技能名/场景标题/剧本名，
不再引入「降级」这类新词，降级与挂起信息一律写在正文。原因取引擎降级类别的中文标签：
队列已满 / 队列等待超时 / 服务繁忙 / 超时 / 网络错误 / 服务端错误 / 输出校验失败 / 服务未启用 / 服务不可用 / 已中断 / 参数错误 / 未知错误。

| 标题 | 内容 | 上限 |
|---|---|---|
| 【AI 叙述】 | 清洗后的正文（建议行已在正文里），落款 `—— 主持人 · <KP 名>（AI 叙述）` | 正文 300 字（实现另留一倍保护） |
| 【AI 叙述】 | 降级：`AI 主持暂时不可用（<中文原因>），本回合由 KP 继续。` | 300 字 |
| 【AI 叙述】 | 连续失败挂起：`AI 主持已持续失败，暂时停用到本局结束或被重新开启。` | 120 字 |

- 降级时先发能回退的剧本原文（降级落款），随后再发一条说明；没有原文可回退时只发说明。不伪造 AI 生成的叙述，内部错误码不直接进群。
- 每个挂起周期只发一次挂起提示；`/trpg ai on` 清除挂起后重新计数。
- §4.3 的降级落款样例适用于「有剧本原文可回退」的场景；引擎无原文可回退时按上表只发说明。

## 4. 关键消息模板样例（5 条）

样例数据取自内置剧本 `coc-example`「雨夜古宅」（2–4 人、1920 年代、约 60 分钟），人名与原型小样一致，便于与 `docs/prototype/one-session-message-flow.md` 对照。

### 4.1 【开团】招募公告（群内）

```text
【开团】《雨夜古宅》开始招募
KP：阿岚　剧本：内置 coc-example
1920 年代 · 调查 · 2～4 人 · 约 60 分钟
老友的一封来信，把你们引到城郊那座没人敢住的宅子。

发送 /trpg join 加入；发送 /trpg status 查看局面。
```

> 350 字放得下；一行一件事；最后一行是「下一步怎么做」。剧本没有 `description` 时省掉摘要行，不写「暂无简介」。

### 4.2 【检定 · 聆听】（群内，带奖励骰）

```text
【检定 · 聆听】小满
1D100 = 34 / 50 → 常规成功
奖励骰 1：十位取 2、7 中较小值。
```

失败时第三行换成损失或后果提示（剧本 `failureHint` 有就带上，没有就不写）：

```text
【检定 · 聆听】小满
1D100 = 88 / 50 → 失败
楼梯上传来很轻的一声响，然后没有下文。
```

- 数值永远写成「骰面 / 门槛 → 等级」，三个位置固定，方便老玩家扫读。
- 大成功写 `→ 大成功（01）`，大失败写 `→ 大失败`。
- SAN 检定用 `【理智】` 标题，第三行写 `SAN 60 → 55（损失 5）`。

### 4.3 【AI 叙述】+ 建议动作（群内，合并窗口只发一条）

```text
【AI 叙述】古宅门前
雨点砸在门环上。老管家周福把门开了一条缝，灯光只够照出他的半张脸，他没有让你们进去的意思。

建议：询问周福来意　观察门廊的地面　等待雨停

—— 主持人 · 阿岚（AI 叙述）
```

AI 降级时同一条位置换成模板叙述，落款必须不同：

```text
【AI 叙述】古宅门前
房门在你们敲到第三下时才开。周福站在门内，没有让开。—— 主持人 · 阿岚（AI 暂不可用，本条为剧本原文）
```

- 正文 ≤300 字（不含标题、建议行与落款），超出截断并在末尾加 `…`（截断后的字数统计以清洗后字符为准，与 AI 主持 一致）。
- 建议行固定以 `建议：` 开头，三项用全角空格分隔，不放句号。
- **落款统一格式 `—— 主持人 · <KP 名>（AI 叙述）`**，降级时换 `—— 主持人 · <KP 名>（AI 暂不可用，本条为剧本原文）`。两种状态都注明来源，新手一眼能看出这行是谁写的、AI 有没有参与；降级款必须含「AI 暂不可用」字样（AI 主持 硬要求）。

### 4.4 【结束】+ 战报（先图后文两条）

第一条是图（无正文）：

```text
［图片：战报 · 《雨夜古宅》· 2 小时 06 分 · 结局「雨夜脱身」］
```

第二条是文字，紧接着发：

```text
【结束】《雨夜古宅》· 结局「雨夜脱身」
你们带着那封没寄出的信走进雨里，身后的灯一盏盏灭了。

时间 2 小时 06 分 · 线索 3/4 · 检定 5 次（成功 3）· 成长 2 人次
战报图见上一条；文字明细发送 /trpg log 查看（保留 30 天）。
```

画图失败时只发一条纯文本，标题换成【战报】且带统计明细（见 §7.4 回退文本）：

```text
【战报】《雨夜古宅》· 结局「雨夜脱身」
结束时间：2026-10-22 21:30　时长：2 小时 06 分
KP：阿岚　玩家：小满、老周
线索：泥脚印、未寄出的信、煤油灯下的影子（3/4）
检定：聆听 成功、侦察 成功、理智 失败（共 3 次）
成长：聆听 50 → 52、侦察 40 → 41
日志：/trpg log 可查看本局记录（保留 30 天）
```

### 4.5 【恢复】重启恢复提示（群内，每群一条）

```text
【恢复】《雨夜古宅》已恢复
当前场景：书房（第 2/4 幕）　已恢复 2 名玩家。
本局在上次重启前正在进行，KP 可发送 /trpg resume 继续。

/trpg status 可以随时查看局面。
```

- 重启不补发恢复前积压的挂起提示（AI 主持 口径）。
- 招募期的局不发【恢复】，招募状态不需要恢复。

## 5. 信息可见性与投递

### 5.1 可见性矩阵（继承原型既定结论）

| 消息 | 发到哪 | 依据 |
|---|---|---|
| 场景叙述、检定、对抗、理智、成长、结束、恢复 | 群内 | 原型步骤 3–7 |
| 线索：名称 + `lockedSummary` | 群内 | 原型 D2 |
| 线索：`unlockedText` 全文 | 私聊 KP | 原型 D2；剧本格式 |
| 角色卡：职业一行 | 群内（【加入】） | 原型 D3 |
| 角色卡：属性、技能、物品全文 | 私聊本人 | 原型 D3 |
| 【KP 提示】合并一条 | 私聊 KP | 原型 D4 |
| NPC `public` / `secret` | 私聊 KP | 原型 D9（不发名牌） |
| 错误、权限、冷却、参数提示 | 回到命令来源处（群内命令回群、私聊命令回私聊） | 指令集 判定顺序 |
| 【战报】图 + 文 | 群内，不 @ 参与者 | 原型 D6 |

### 5.2 私聊不可达

QQ 侧的私聊失败分三种，回退口径按顺序试：

1. 私聊投递失败（返回 retcode 非 0）→ 群内发一行【提示】：`小满 的私聊不可达，角色卡全文未发出，可在 QQ 设置里放开临时会话后重发 /trpg pc。`
2. 连续 2 次私聊失败 → 该成员本局后续私聊改为群内折叠发送（只发「职业 + 关键数值」一行，不发全文），并在本局结束时不再提示。
3. 涉及秘密的信息（线索全文、KP 提示、NPC secret）**绝不回退到群内**，失败就只提示，宁缺不泄（原型 D4）。

### 5.3 投递顺序与合并

- 同一事件要发多条时按「图 → 文」顺序发（保证图先到）。
- 同一回合的多条群内消息之间不主动加延时；顺序由按群串行锁保证。
- 合并窗口内只发一条 AI 叙述（AI 主持）：窗口内的模板叙述不单独补发，直接并入这一条。

### 5.4 失败与重试

- 任何一条 send 失败只记 WARN 日志，不重试、不影响状态迁移（状态在发送前已落库）。
- 关键消息（【开团】【开局】【结束】）发送失败时，在群内补发一行【提示】：`上一条消息发送失败，可发送 /trpg status 查看当前局面。`，不重发正文。
- 图片发送失败与图片渲染失败同路径处理（§7.4）。

## 6. 超长处理

### 6.1 拆分规则

- 群内单条正文上限 **500 字**（标题与折叠行不计）。
- 拆分点优先级：段落 `\n\n` → 行 `\n` → 中文强标点 `。！？` 与 `…` → 中文弱标点 `，、；：`。回扫窗口 60 字，找不到就硬切（与仓内 `RoleplayMessageSender` 的强/弱标点回扫思路一致，阈值不同）。
- **最多拆 3 条**：第 1 条带标题，第 2、3 条标题追加 ` · 续 2/3`、` · 续 3/3`；仍超出则第 3 条末尾折叠成 `……（本条还有 N 字，发送 /trpg log 查看）`。
- 私聊不拆条，超长直接在单条末尾折叠同款提示（私聊被折叠比多收几条更不容易出错）。
- 剧本侧上限已比本规更严（`narration` ≤1200、`ending.narration` ≤1200、`unlockedText` ≤800），超长主要出现在 AI 叙述、列表类消息（剧本库、日志）与拼接消息（结束 + 战报）。

### 6.2 分页（列表类）

| 消息 | 每页 | 翻页方式 |
|---|---|---|
| 【剧本库】列表 | 10 条 | `/trpg script list <页码>` |
| 日志（私聊或群内） | 10 条 | `/trpg log [页码]`，按 seq 倒序（数据模型与存档） |
| 【战报】文字明细 | 不翻页，折叠 | —— |

## 7. 图片版式与失败回退

### 7.1 三种图片

| 图片 | 触发 | 发到哪 | 正文 |
|---|---|---|---|
| 情景卡 | 进入场景时自动生成（开关 `presentation.sceneImage`），不新增指令 | 群内 | 无，图就是消息 |
| 战报 | 局结束结算完成 | 群内 | 无 |
| 脚本打印页 | `/trpg script show <id>` 的私聊长输出 | 私聊 | 无 |

角色卡、检定结果、/r 结果**不发图**。

### 7.2 版式（`ImageUtil.renderText` 760px）

主程序 API 只有 `ImageUtil.renderText(String title, List<String> lines)` 与 `ImageUtil.toBase64Uri(byte[])`，画布宽 760px，行数与行宽由主程序控制，插件不引 AWT 自绘（保持「只依赖 API」的边界）。因此版式要素靠**行约定**表达：

- 标题行放卡片名：`战报 · 《雨夜古宅》`。
- 第一行放元信息：`2026-10-22 · 2 小时 06 分 · 结局「雨夜脱身」`。
- 第二行开始分节，节名独立成行并前置两字放不下就换行的守卫：节名一律 `【节名】`，与正文分属不同 `lines` 元素。
- 每行确保不超过 **26 个全角字符**（760px 下按主程序字号估算，超过会被裁掉），超出由本插件的 `wrapForImage` 预先折行。
- 不用空格对齐表格，改用「标签：值」单行式，避免字体度量差异。

### 7.3 情景卡与战报的栏目

**情景卡**（≤14 行）：

```text
【场景】书房 · 第 2/4 幕
【在场】小满、老周
【线索】泥脚印、未寄出的信
书桌上摊着一本翻开的账簿，最后一页被撕走了；
煤油灯照出墙上的一道细缝，缝里透出冷风。
【下一步】小满：观察书桌；老周：查看墙缝
```

行数构成：标题 1 + 元信息行 1 + 栏目标签行 ≤3 + 叙述 4～6 + 下一步 1，合计 ≤12 行，留 2 行余量（上限 14 行）。

**战报图**（≤22 行，超出只截取到 22 行并在最后一行写「其余见 /trpg log」）：

```text
【局】《雨夜古宅》
【时间】2026-10-22 19:24 — 21:30（2 小时 06 分）
【KP】阿岚
【玩家】小满、老周
【结局】雨夜脱身
【线索】泥脚印 / 未寄出的信 / 煤油灯下的影子（3/4）
【检定】独立检定 3 次：聆听 成功、侦察 成功、理智 失败
【成长】聆听 50 → 52、侦察 40 → 41
【日志】/trpg log 可查看本局记录（保留 30 天）
```

超长处理：玩家或线索名单超过 3 行时，该栏折叠为「小满、老周 等 6 人」，并在末行追加「其余见 /trpg log」；总行数超过 `imageMaxLines`（默认 22）时只截取到上限行。

### 7.4 失败回退（冻结文本）

统一模式（仓内三处既有先例：`MBB-Help/HelpCommand.java:96-100`、`MBB-Status/StatusCommand.java:46-52`、`MBB-Roleplay/RoleplayEmotionCommandHandler.java:42-51`）：

1. 渲染返回 `null` 或抛异常 → 记 WARN 日志（含图片类型与局号）。
2. 情景卡 → 改发【场景 · 标题】纯文本，正文用该场景叙述（AI 关闭或不可用时用 `fallbackNarration`），并带一行 `发送 /trpg status 查看局面。`。
3. 战报 → 改发【战报】纯文本，字段与图一致（见 §4.4 第二例）。
4. 脚本打印页 → 改发私聊纯文本，按 §6.1 折叠。
5. 回退后**不再重试**渲染；同一局内再触发同样图片时照常尝试（渲染失败多为环境问题，可能是暂时的）。

## 8. 实现落点与配置

### 8.1 类（按角色装配顺序排）

| 类 | 职责 | 可测性 |
|---|---|---|
| `TrpgMessageTemplates` | 全部模板的静态方法，输入值对象，输出未拆分的单个字符串 | 纯函数，单测主目标 |
| `TrpgMessageFormatter` | 清洗（去 Markdown 残符、去 emoji、规整空白）、字数统计、`maxChars` 截断 | 纯函数，单测 |
| `TrpgMessageSplitter` | 按 §6.1 拆分与折叠 | 纯函数，单测 |
| `TrpgImageTemplates` | 情景卡 / 战报 / 脚本页的 `List<String>` 组装 + `wrapForImage` | 纯函数，单测 |
| `TrpgPresenter` | 统一出口：模板 → 格式化 → 拆分 → 图片渲染（调 `ImageUtil`）→ 发送 → 失败回退 | 用一个 `FakeSender` 测 |
| `TrpgPresentConfig` | 配置读取（`groupMaxChars`、`privateMaxChars`、`splitMax`、`sceneImage`、`reportImage`、`imageMaxLines`、`style`） | 读默认值 |

### 8.2 配置项（`config.yml` 内 `presentation` 节）

| 键 | 默认 | 说明 |
|---|---|---|
| `presentation.groupMaxChars` | 500 | 群内单条正文上限 |
| `presentation.splitMax` | 3 | 单次最多拆几条 |
| `presentation.privateMaxChars` | 1200 | 私聊单条上限（超过折叠） |
| `presentation.style` | `broadcast` | 非 `broadcast` 按 `broadcast` 处理并 WARN |
| `presentation.sceneImage` | `true` | 情景卡开关 |
| `presentation.reportImage` | `true` | 战报图开关 |
| `presentation.imageMaxLines` | 22 | 战报图最大行数 |

配置项都要写进 `docs/MBB-Trpg.md` 的配置表（规格装配 负责装配）并同步 `update.md`。

### 8.3 边界（不做的事）

- 不引入 AWT 自绘（`StatusImageRenderer` 那种），保持「插件只依赖 `org.moboxlab.moboxbot.API`」。
- 不做图片缓存、不做合并图、不做二维码或分享图。
- 不在群里发 Markdown、不 @ 参与者、不发语音。
- 不提供 B 沉浸风 / C 极简风的实现，配置位留白。

## 9. 验收与测试

### 9.1 验收清单

1. 按 §4 的 5 条样例，逐条与实现输出对比，字符与换行一致。
2. 一条超长事件（拼接后 1400 字）只拆成 3 条，第 3 条带折叠提示。
3. 把 `ImageUtil` 打桩返回 `null` 时，情景卡与战报都退化为纯文本，且局可以正常结束。
4. 私聊不可达时只发群内提示，线索全文与 KP 提示不出现于群内。
5. 同一次合并窗口内的多条模板叙述只出现一条。
6. 所有标题都在 §2.3 词表内，无 emoji。

### 9.2 测试

- 本仓库**当前没有测试目录，也没有任何测试执行步骤**：根目录 `build-all.ps1` 只做编译打包，`.github/workflows/build.yml` 只有 `Build MoBoxBot` 与 `Build plugins` 两步。JUnit 4.13.2 + hamcrest-core 1.3 的接入口径已在 数据模型与存档 定过（构建脚本下载并校验 sha1），但脚本与 CI 里的开关都还没落地，这是 实现切片「实现切片与开工清单」的必需前置；本文连同 §8.1 的五个可测类一起把这条依赖显式登记给 实现切片。
- 纯函数四件套（`Templates` / `Formatter` / `Splitter` / `ImageTemplates`）可用普通 `main` 断言自测，不依赖 JUnit 也能覆盖 §9.1 的 1、2、6。
- `TrpgPresenter` 用一个实现 `CommandSender` 的 `FakeSender` 收集消息段，覆盖 3、4、5。

## 10. 未决

- 情景卡是否要等到「AI 叙述 + 场景叙述合并成一条」之后才发，取决于 AI 主持 合并窗口在实现时的实际投递顺序，归 实现切片 在切片里定，本文只定版式与开关位。
- 图片行宽 26 字是按主程序 `renderText` 的 760px 与默认字号估算的；真机出图后若裁字，只改 `wrapForImage` 的常量，不改本文件的其他口径。
